# MAX-подписчик: настройка и проверка

Доставка уведомлений о новых закупках в канал мессенджера **MAX** через
официальный Bot API. MAX — российский мессенджер (ранее VK Макс), доступный из
РФ без прокси, поэтому он подходит как альтернатива Telegram, если
`api.telegram.org` недостижим.

> Документация MAX Bot API: <https://dev.max.ru/docs-api>.
>
> Бэкенд MAX реализован в парсере (`MaxBackend`), подключён к диспетчеру
> `Notifier` и конфигу `notifications.max`.

## Принцип работы

- Эндпоинт: `https://platform-api2.max.ru/messages`
- Аутентификация: токен в заголовке `Authorization: <token>` (не в query!).
- Отправка в канал: `POST /messages?chat_id={chat_id}` + тело
  `{"text": "...", "format": "html"}`.
- Формат HTML — тот же, что в Telegram (`<b>`, `<i>`, `<a href>`, `<code>`,
  `<blockquote>` и т.д.), поэтому HTML-карточка из `render_telegram_message`
  совместима без изменений.
- `chat_id` канала — **только числовой**, получается через подписку на события.

## 1. Создать бота и получить токен

1. Откройте мини-приложение **«MAX для бизнеса»** (или
   [business.max.ru](https://business.max.ru/self)).
2. Пройдите верификацию профиля (требуется **юрлицо / ИП / самозанятый,
   резидент РФ**).
3. Раздел **Чат-боты** → **Перейти** → **Расширенные настройки** → **Настроить**.
4. Скопируйте `access_token` (в альтернативе — команда **«Получить токен»**
   в боте «MAX для бизнеса»).

> Токен **секретный**: задаётся только через переменную окружения, в git не
> попадает. Может быть отозван платформой за нарушения.

## 2. Создать канал

В приложении MAX: **Создать канал** → название + описание.

## 3. Добавить бота в канал

В канале: **Управление** → **Участники** / **Добавить** → добавьте созданного
бота участником/администратором. Бот должен состоять в канале, иначе он не
сможет постить.

## 4. Получить chat_id канала

У MAX нет «@username»-адресации — нужен числовой `id`. Он приходит только через
**подписку на события** (Long Polling / Webhook `GET /updates`).

### Утилита `scripts/get_max_chat_id.py`

В репозитории есть утилита, которая сама опрашивает `GET /updates` и ждёт
событие от канала:

1. Токен бота должен быть в `ZAKUPKI_MAX_TOKEN` (в `.env` корня проекта или
   в окружении).
2. Запустите утилиту и в течение таймаута напишите сообщение в канал (или
   добавьте бота — придут события `bot_added` / `bot_started`):

   ```bash
   .venv/bin/python scripts/get_max_chat_id.py --insecure
   ```

   Флаг `--insecure` отключает проверку TLS-сертификата MAX (сертификат
   Минцифры может отсутствовать в доверенных). Если сертификат доверенный,
   флаг можно опустить.

   Утилита выведет найденный числовой `chat_id` и готовую строку для конфига:
   `chat_id: "<id>"`.

   Дополнительные параметры: `--timeout <сек>` (по умолчанию 60) и `--url`.

Пример полученного `chat_id` (числовой, `int64`), например `123456789012345678`.

> Без подписки получить `chat_id` нельзя (метод `GET /chats` с июня 2026 не
> поддерживается).

## 5. Проверка доставки

### Утилита `scripts/test_max_chat.py`

Отправляет тестовое сообщение в канал с известным `chat_id`. Токен берётся из
`ZAKUPKI_MAX_TOKEN`, `chat_id` — из `ZAKUPKI_MAX_CHAT_ID` (или `--chat-id`):

```bash
.venv/bin/python scripts/test_max_chat.py --insecure
```

Если в канале появилось «Тест: проверка доставки в канал MAX» — бот и `chat_id`
рабочие. Флаг `--insecure` — как в утилите из шага 4 (сертификат MAX может
отсутствовать в доверенных). Дополнительно: `--text`, `--url`.

### Вручную (curl)

```bash
export ZAKUPKI_MAX_TOKEN="<access_token>"
export ZAKUPKI_MAX_CHAT_ID="<chat_id>"

curl -X POST "https://platform-api2.max.ru/messages?chat_id=$ZAKUPKI_MAX_CHAT_ID" \
  -H "Authorization: $ZAKUPKI_MAX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"text": "<b>Тест</b>: проверка доставки", "format": "html", "disable_link_preview": true}'
```

Если в канале появилось «Тест: проверка доставки» — бот и `chat_id` рабочие.

## 6. Подключение к парсеру

Задайте токен (в `.env` / CI, не в git):

```bash
export ZAKUPKI_MAX_TOKEN="<access_token>"
```

В `configs/config_service.yaml`:

```yaml
notifications:
  backend: "max"
  max:
    enabled: true
    chat_id: "123456789012345678"   # числовой id канала из шага 4
```

Затем запустите один проход и проверьте, что карточка ушла в канал:

```bash
uv run zakupki-parser --configs configs check-config
uv run zakupki-parser --configs configs run-once
```

## 7. Ограничения и особенности

- **2 сообщения/сек в один чат** — при потоке новых закупок делайте задержку.
- Лимит платформы ~**30 запросов/сек** на `platform-api2.max.ru`.
- `text` — до **4000 символов** (текущая карточка короче, но учитывайте).
- Для каналов поле `notify` должно быть `true` (или отсутствовать) — посты в
  каналы без push не отправляются.
- Требуется доверенный сертификат (в т.ч. сертификат Минцифры) в доверенных.
- Ошибка отправки логируется как `warning` и не ломает проход парсера.
