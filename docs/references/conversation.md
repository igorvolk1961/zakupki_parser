1. Ключевые решения:

    - **Экономичный многоуровневый анализ**: Подтвержден подход к экономии токенов LLM. Система работает каскадом:
        - Векторная фильтрация заведомого мусора;
        - Предварительная проверка только по описанию закупки (дешево);
        - Глубокий LLM-анализ Технического задания только для случаев, прошедших предварительную фильтрацию.
        - Рассмотреть альтернативы применению LLM.
        - Если есть критическая необходимость применить LLM, использовать дешевые, например, локальные opensource-решения.
    - **Слова-исключения**: Необходимо проверять ключевые слова, которых не должно быть в описании тендера. Напрмер, если компания не имеет компетенций в сфере медицины, но нужно добавить слово-исключение: "медицинский". Если есть ключевое слово "искусственный" (интеллект), но нужно добавить слова-исключения: "ель", "лед", "алмаз".
    - **Специфические фильтры**: Для повышения точности необходимо внедрить проверку специфических условий, а не только ключевых слов:
        - ##Требование опыта##: Важно не просто жестко отсеивать тендеры с требованием опыта исполненных контрактов (например, по ПП РФ № 2571), а маркировать их. Иногда это жесткое огрничение допуска к тендеру, а иногда требование просто дает дополнительные баллы или допускает подтверждение опыта сканами актов.
        - ##Реестр Минпромторга##: Учет требований к российскому происхождению товара. Система должна корректно считывать нюансы, например, игнорировать длинные юридические преамбулы, если в конце стоит пометка «не установлено».
        - ##Лицензирование##: Фильтрация по наличию обязательных лицензий для специфических работ.
    - **Конкурентное преимущество**: В отличие от агрегаторов (Tenderplan, Tenderland), которые просто выдают «сырой» список по ключевым словам, ценность нашего сервиса должна быть в предварительно проверенной сводке. Система должна проверять 5–10 специфических параметров клиента (например, форма отходов, объем, локация, лицензии), экономя тендерному специалисту 1–1,5 часа ручной проверки ежедневно.
    - **Фокус на результате**: На текущем этапе приоритетом является экономика (дешевизна эксплуатации) и бизнес-результат (качественный отбор), а не  погружение в технические детали разработки.
