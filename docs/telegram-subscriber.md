# Telegram-подписчик: настройка и проверка

Включите парсеру реальную доставку уведомлений о новых закупках в
Telegram-канал. Ниже — пошаговая инструкция и проверка.

## 1. Создать бота

1. В Telegram откройте диалог с **[@BotFather](https://t.me/BotFather)**.
2. Команда `/newbot`.
3. Укажите отображаемое имя и username (обязательно заканчивается на `bot`).
4. Скопируйте выданный токен (формат `123456789:ABC-...`).

> Токен **секретный**: задаётся только через переменную окружения, в git не
> попадает.

## 2. Создать канал

«Создать канал» → название + описание. Тип:
- **публичный** — задайте username, например `@my_zakupki_test`;
- **приватный** — канал без username, доступ по приглашению.

## 3. Добавить бота администратором

Канал → «Управление» / настройки → «Администраторы» → «Добавить
администратора» → выберите бота → выдайте право **«Отправка сообщений»**.

> Бот обязан быть администратором канала — иначе сообщения не уйдут.

## 4. Определить chat_id

- **Публичный канал** — используйте username напрямую:
  `chat_id = "@my_zakupki_test"`.
- **Приватный канал** — нужен числовой `id`. Напишите в канал любое сообщение,
  затем в бота **@RawDataBot** перешлите его (или получите id через
  `getUpdates`). Он покажет `id` вида `-1001234567890`.

## 5. Настройка парсера

Задайте токен (в `.env` / CI, не в git):

```bash
export ZAKUPKI_TELEGRAM_TOKEN="123456789:ABC-..."
```

В `configs/config_service.yaml`:

```yaml
notifications:
  backend: "telegram"
  telegram:
    enabled: true
    chat_id: "@my_zakupki_test"   # или -1001234567890 для приватного
```

## 6. Проверка

Включите площадку в `sites`, затем:

```bash
uv run zakupki-parser --configs configs check-config
uv run zakupki-parser --configs configs run-once
```

В канале появится HTML-карточка закупки. Для ручной проверки без сайта —
небольшой pytest с `httpx.MockTransport` (см. `tests/unit/test_telegram_notify.py`)
или временный скрипт, шлющий `render_telegram_message` на `sendMessage` при
заданном токене.

## Примечания

- Ошибка отправки (лимиты, недоступность API) логируется как `warning` и **не**
  ломает проход парсера.
- Telegram лимитирует ~20 сообщений/мин; при потоке новых закупок сообщения могут
  упереться в лимит — это вне scope, достаточно таймаута и лога.
