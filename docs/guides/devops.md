# Руководство DevOps

Роль **DevOps** предназначена для эксплуатации системы: управления парсером,
конфигурациями фоновых сервисов и логированием.

Рабочее пространство DevOps включает панель **«Парсер»** вверху страницы и
вкладки: **Парсер**, **Сервисы**, **Конфигурация**, **Управление логами**,
**Логи**, а также **Личный кабинет**. Если у пользователя несколько ролей,
вкладки всех его ролей объединяются в один интерфейс, а в меню «Документация»
появляется отдельный пункт на каждую роль.

## 1. Вход

Вход выполняется по логину и паролю (Bearer-токен создаётся на сервере).
Заблокированная учётная запись (`blocked`) войти не может.

## 2. Панель «Парсер»

Кнопки управления сбором в верхней части страницы:

- **▶ Запустить** — запускает постоянный мониторинг парсера (периодические
  проходы). Во время работы кнопка становится недоступной.
- **■ Остановить** — останавливает текущий проход (браузер корректно
  закрывается).
- **Очистить БД** — диалог очистки БД: всё / только неактивные / нерелевантные
  с порогом fit-score. Доступна только при остановленном парсере; требует
  подтверждения. Закупки, принятые «в работу», по умолчанию сохраняются —
  удаление только по явной отметке в диалоге.

Рядом выводится статус парсера: «не запущен», «работает…», «остановлен», либо
сообщение об ошибке и время завершения.

## 3. Сервисы

Под-вкладки на каждый фоновый сервис (**Скоринг**, **Анализ документов**,
**P(win)**, **Margin**): форма по схеме `src/<service>/config.yaml`
(сгруппирована по смыслу) + **«Текстовый режим»** с сырым YAML.

Секреты сервиса редактируются в модальном окне **«Секреты (.env)»** (формы
`KEY=VALUE`) и в `config.yaml`/форму не попадают.

Кнопка **«⟳ Перезагрузить»** (у сервисов **Скоринг** и **Анализ документов**)
перезапускает соответствующий фоновый сервис (останавливает работающий воркер
и поднимает его заново).

Изменения применяются при следующем старте сервиса.

## 4. Конфигурация

Форма для `config_ops.yaml` (+ **«Текстовый режим»** с сырым YAML). Секреты
(auth.secret, токены уведомлений) через API не редактируются — они берутся из
env. Изменения применяются при следующем старте сервиса. Флаг
`auto_start_monitoring` управляет автозапуском цикла мониторинга при старте
сервиса (по умолчанию включён); при выключенном флаге мониторинг запускается
только кнопкой на панели парсера.

## 5. Управление логами

Форма для `config_log.yaml` (+ **«Текстовый режим»** с сырым YAML): уровень
логирования и другие параметры сбора логов. Изменения применяются при
следующем старте сервиса.

## 6. Логи

Просмотр хвоста файла лога: выбор файла (парсер + фоновые сервисы), поиск по
тексту, фильтр по уровню («ошибки»/«предупреждения») и по диапазону дат, число
строк, автообновление. Логи всех сервисов хранятся в `data/logs/`.

## 7. Парсер (конфигурация парсера)

Форма по схеме `config_parser.yaml`: параметры браузера и антиблок-мер
(задержки, User-Agent, stealth, лимиты) + **«Текстовый режим»** с сырым YAML и
кнопкой **«Сохранить»**. Изменения применяются при следующем старте сервиса.
Кнопка **«⟳ Перезагрузить»** перезапускает парсер (останавливает текущий проход
и запускает постоянный мониторинг заново).

## 8. Личный кабинет

Вкладка «Личный кабинет» (или кнопка «Кабинет» в шапке) позволяет управлять
собственными аккаунтами и платными опциями, триал-режимом и сменой пароля.
