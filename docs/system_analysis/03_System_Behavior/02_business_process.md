# Диаграмма бизнес-процесса: от сбора закупок до карточки «В работу»

> Назначение: простое описание процесса для бизнес-стейкхолдера.
> Ключевые акценты: глубокий анализ ТЗ запускается **по решению пользователя**;
> отсев по условиям, которым компания не удовлетворяет (опыт, реестр Минпромторга,
> лицензии и любые другие произвольные условия ТЗ).

```mermaid
flowchart LR
  subgraph P1[Парсер]
    A[Сбор закупок по кодам ОКПД2] --> B[Фильтр по ключевым словам<br>и словам-исключениям]
  end
  subgraph P2[Лёгкий скоринг]
    B --> C[Оценка Fit]
    C --> D{Fit ≥ порога?}
  end
  D -- Нет --> X1[Закупка отсеяна]
  D -- Да --> E[Предварительный список]
  subgraph P3[Решение пользователя]
    E --> F[Пользователь выбирает,<br>какие закупки направить<br>на глубокий анализ]
  end
  F --> G[Глубокая обработка ТЗ]
  subgraph P4[Глубокая обработка ТЗ]
    G --> M{Стандартные условия:<br>опыт 2571, реестр<br>Минпромторга, лицензии}
    G --> K{Другие условия ТЗ?<br>произвольные требования}
  end
  M -- соответствует --> L[Карточка<br>«В работу»]
  K -- соответствует --> L
  M -- не соответствует,<br>запрет абсолютный --> X2[Закупка отсеяна]
  K -- не соответствует,<br>запрет абсолютный --> X2
  M -- не соответствует,<br>запрет не абсолютный --> N[Закупка не отбрасывается,<br>а маркируется 🟡]
  K -- не соответствует,<br>запрет не абсолютный --> N
```

## Пояснения

- **Парсер** собирает закупки по кодам ОКПД2 и отсеивает по ключевым словам и
  словам-исключениям (клиентская пост-фильтрация до записи в БД).
- **Лёгкий скоринг** — дешёвая оценка Fit: закупки ниже порога не попадают в список.
- **Решение пользователя** — именно пользователь (тендеролог) решает, какие закупки
  из предварительного списка направить на глубокий анализ.
- **Глубокая обработка ТЗ** — анализ текста ТЗ на соответствие условиям компании:
  опыт (ПП РФ 2571), реестр Минпромторга, лицензии, а также любые другие произвольные
  требования. Исходы проверки:
  - все условия выполнены → закупка становится карточкой «В работу»;
  - несоответствие с **абсолютным запретом** → закупка отсеивается полностью;
  - несоответствие с **неабсолютным (мягким) запретом** → закупка не отбрасывается,
    а маркируется 🟡 (требует внимания) и остаётся доступной тендерологу.
