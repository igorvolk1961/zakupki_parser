# Шаблон карточки тендера (требование к UI/данным)

> Требование к представлению карточки закупки (SA-4.3): поля, маркеры, дисклеймер.
> Покрывает US-3.2, US-4.5, US-6.2 и NFR-SEC-4. Связано с `07_UI/01_ui_requirements.md`.

## 1. Базовые поля карточки (US-3.2)

| Поле | Источник в API | Обязательность |
| :--- | :------------- | :------------- |
| Реестровый номер | `number` | ✅ |
| Площадка | `platform_id` | ✅ |
| Заказчик | `customer` | ✅ |
| Закон | `law` (44-ФЗ / 223-ФЗ) | ✅ |
| НМЦК | `nmck` | ✅ |
| Дедлайн подачи | `deadline` | ✅ |
| Срок исполнения | `execution_term` | ⬜ |
| Обеспечение/аванс | `security_amount`, `advance` | ⬜ |
| Коды ОКПД2/КПГЗ | `okpd2_codes`, `kpgz_codes` | ✅ |
| Предмет закупки | `subject` | ✅ |
| Тип процедуры | `procedure_type` | ✅ |
| Fit | `fit_score` | ✅ |
| P(win) / Margin | `p_win`, `margin` | ⬜ (если считались) |
| Ссылка на ЭТП | `url` | ✅ |
| Статус | `status` (этап 7) | ⬜ |

## 2. Анализ документов (US-4.5; реализовано)

Раздел «Анализ документов» карточки. Стоп-условия задаёт профиль; встроенных
неотключаемых проверок нет.

| Блок | Источник | Что показано |
| :--- | :------- | :----------- |
| Требования к участнику: лицензии | детерминированно по всем документам + лицензии профиля | какой вид требуется и есть ли он у поставщика; «вид не распознан» — требует проверки |
| Требования: опыт, реестр Минпромторга | детерминированно (`scoring_common.requirements`) | найдено / требуется / «не требуется» (BR-04: «не установлено» — не блокирует) |
| Допустимость соисполнителей | по всем документам | разрешено / запрещено / ограничено (с лимитом, %) / неясно |
| Отчётные поля профиля | LLM извлекает значение, код проверяет условие | значение (у списка — сколько найдено LLM и дополнено), условие, ✓ / ✗ / ⚪ «не проверено: причина», ⏳ «сайт собирается»; у нарушивших — причина по значению («нет в источнике», «нет рядом: утилизации»), требования из ТЗ с метками сайта |
| Расстояние | гео (центр региона профиля) | км до ближайшего центра, лимит |
| Вердикт | `requirement_severity` (опыт — BR-03) + поля с уровнем барьера | принята / не принята и причины (жёсткие барьеры); «снижают P(win)» и причины (мягкие), P(win) модели → итоговый; не принятая авто-отклонена |

Жёсткий барьер выделен красным, мягкий — янтарным (и в Excel-выгрузке карточки).
Опыт (BR-03): через площадку ПП 2571 без опыта «через площадку» в профиле — жёсткий;
сканы договоров/актов или выписка из реестра — мягкий; только критерии оценки — не барьер.

## 3. Дисклеймер (NFR-SEC-4, US-9.1)

Внизу карточки (и в подвале экспортов) обязателен текст:

> «Результаты автоматизированного скоринга носят исключительно информационный
> характер и не являются юридической консультацией. Окончательное решение о
> соответствии требованиям закупки и подаче заявки принимает пользователь».
