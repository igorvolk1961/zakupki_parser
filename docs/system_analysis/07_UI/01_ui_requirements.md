# Требования к UI/UX

> Описание экранов web-приложения (web-интерфейс, `src/zakupki_parser/api/zakupki.html`) как
> требований к интерфейсу MVP и целевой модели. Связано с US/FR (экраны — по эпикам).

## 1. Экраны MVP (реализованы в web-интерфейсе)

### Э1. Вкладка «Закупки» (US-3.2, US-2.3)
- Таблица закупок с колонками: номер, заказчик, закон, НМЦК, дедлайн, предмет, Fit, статус, ссылка на ЭТП.
- Сортировка по убыванию Fit (по умолчанию); фильтры: «Только активные», «Только релевантные» (`min_fit_score`), «Только оценённые» (`scored`), поиск по ОКПД2/заказчику/номеру.
- Переключатель «Только релевантные» использует порог `notify_min_fit_score` (`GET /api/config/threshold`).
- Клик по строке — карточка закупки (модальное окно): базовые поля + «Анализ ТЗ (стоп-условия)» с вердиктами и маркерами 🔴/🟡/🟢 по системным проверкам (опыт 2571, реестр Минпромторга, лицензии/СРО; плашка «обязат.») и по вопросам клиента.
- Кнопка «Анализировать ТЗ» — вызов `POST /api/procurements/analyze` (для выбранных), статус «queued», обновление через WebSocket `/ws`.
- Решения по карточке (Эпик 5, US-5.1–5.6): кнопки «В работу»/«Снять с работы» и «Отбраковать»; «Отбраковать» открывает модальное окно с полем причины и опциями «убрать ключевые слова, по которым отобрана закупка» и «добавить слово-исключение». Отклонённые скрываются из выдачи; признак «в работе» (`in_work`) показывается в таблице и в карточке.

### Э1.1. Вкладка «В работе» (US-5.4–5.6, Эпик 5)
- Единый механизм с вкладкой «Закупки»: список берётся тем же эндпоинтом
  (`GET /api/procurements?in_work=true`), обработка карточки (анализ ТЗ, скоринг,
  RAG) идентична результатам поиска. Единственное отличие: для закупок «в работе»
  недоступны операции «В работу» и «Отбраковать» — доступно «Снять с работы».
- Приём по URL ЭТП (поле + кнопка «Принять в работу по URL»): закупка с таким URL
  привязывается к записи, иначе создаётся запись-снимок по URL.
- Записи-снимки по URL без закупки в базе (в т.ч. после очистки БД, BR-08)
  показываются отдельным блоком с удалением.

### Э2. Вкладка «Заказчики» (справочник)
- Таблица заказчиков: наименование, ИНН, рейтинг; поиск по имени/ИНН.
- Карточка заказчика с историей закупок.

### Э3. Вкладка «Параметры» (аналитические настройки)
- Редактирование `config_service.yaml` (JSON-редактор + сохранение через `PUT /api/config`).
- Эксплуатационные параметры и секреты не редактируются через UI.

### Э4. Вкладка «Промпты»
- Просмотр/редактирование файлов промптов `scoring_service` (`GET/PUT /api/prompts/{name}`) и `analysis_service` (`GET/PUT /api/analysis-prompts/{name}`); JSON-файлы валидируются.
- Переключение между сервисами — селектором во вкладке; изменения применяются при следующем старте соответствующего сервиса.

### Э5. Вкладка «Профили» (Эпик 1, US-1.1–1.4)
- CRUD профилей: название, ключевые слова/исключения, целевые ЭТП/законы, ОКПД2, диапазон НМЦК, порог Fit.
- Переключение активного профиля (`POST /api/clients/{id}/activate`).
- Сид из `файл-сид профиля` (`POST /api/clients/seed`).
- Во вкладке «Вопросы по ТЗ» — read-only блок «Обязательные проверки» (системные проверки `sys:*`: опыт 2571, реестр Минпромторга, лицензии/СРО); они не редактируются и не сохраняются в профиль (FR-4.4).

### Э6. Вход (US-7.1)
- Форма логина (имя/пароль) и регистрации; роль тендеролог; токен в localStorage.
- Админ-действия (запуск/остановка парсера, очистка БД, редактирование конфигурации/промптов) доступны только администратору (`require_admin`); просмотр закупок/заказчиков — авторизованному пользователю.

## 3. Целевые экраны (пост-MVP)

> Карточка с маркерами 🔴/🟡/🟢 по системным проверкам, решения по карточке
> («В работу»/«Отклонить», Э1/Э1.1) и вкладка «В работе» реализованы в MVP;
> дисклеймер (US-9.1) и «предложение» слова-исключения (US-5.3) — пост-MVP.
