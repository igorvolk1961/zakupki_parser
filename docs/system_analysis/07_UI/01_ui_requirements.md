# Требования к UI/UX

> Описание экранов web-приложения (web-демо, `src/zakupki_parser/api/zakupki.html`) как
> требований к интерфейсу MVP и целевой модели. Связано с US/FR (экраны — по эпикам).

## 1. Экраны MVP (реализованы в web-демо)

### Э1. Вкладка «Закупки» (US-3.2, US-2.3)
- Таблица закупок с колонками: номер, заказчик, закон, НМЦК, дедлайн, предмет, Fit, статус, ссылка на ЭТП.
- Сортировка по убыванию Fit (по умолчанию); фильтры: «Только активные», «Только релевантные» (`min_fit_score`), «Только оценённые» (`scored`), поиск по ОКПД2/заказчику/номеру.
- Переключатель «Только релевантные» использует порог `notify_min_fit_score` (`GET /api/config/threshold`).
- Клик по строке — карточка закупки (модальное окно): базовые поля + «Анализ ТЗ (стоп-условия)» с вердиктами по вопросам профиля.
- Кнопка «Анализировать ТЗ» — вызов `POST /api/procurements/analyze` (для выбранных), статус «queued», обновление через WebSocket `/ws`.

### Э2. Вкладка «Заказчики» (справочник)
- Таблица заказчиков: наименование, ИНН, рейтинг; поиск по имени/ИНН.
- Карточка заказчика с историей закупок.

### Э3. Вкладка «Параметры» (аналитические настройки)
- Редактирование `config_service.yaml` (JSON-редактор + сохранение через `PUT /api/config`).
- Эксплуатационные параметры и секреты не редактируются через UI.

### Э4. Вкладка «Промпты»
- Просмотр/редактирование файлов промптов (`GET/PUT /api/prompts/{name}`); JSON-файлы валидируются.

### Э5. Вкладка «Профили» (Эпик 1, US-1.1–1.4)
- CRUD профилей: название, ключевые слова/исключения, целевые ЭТП/законы, ОКПД2, диапазон НМЦК, порог Fit.
- Переключение активного профиля (`POST /api/clients/{id}/activate`).
- Сид из `data/profile.md` (`POST /api/clients/seed`).

### Э6. Вход (US-7.1)
- Форма логина (имя/пароль) и регистрации; роль тендеролог; токен в localStorage.
- Админ-действия (запуск/остановка парсера, очистка БД, редактирование конфигурации/промптов) доступны только администратору (`require_admin`); просмотр закупок/заказчиков — авторизованному пользователю.

## 2. Требования к поведению

| # | Требование | Связано с |
| :-: | :--------- | :-------- |
| UI-1 | Список закупок обновляется без перезагрузки страницы (WebSocket «data-changed») | US-3.2, FR-2.6 |
| UI-2 | Закупки с Fit ниже порога помечаются «низкий приоритет», но не скрываются (если включено) | US-2.2/2.3 |
| UI-3 | При пустой выдаче показывается информационное сообщение (не пустой экран) | — |
| UI-4 | Тяжёлые операции (анализ ТЗ) не блокируют UI: статус «Идет анализ...» → обновление по WebSocket | US-4.1, NFR-PERF-2 |
| UI-5 | Роль пользователя определяет видимость админ-блока (парсер, очистка БД, конфиг) | US-7.6, US-8.2 |
| UI-6 | Валютные/числовые поля и даты форматируются единообразно (НМЦК, дедлайн) | US-3.2 |
| UI-7 | Внешние ссылки на ЭТП открываются в новой вкладке | US-3.2 |
