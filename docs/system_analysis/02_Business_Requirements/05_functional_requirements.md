# Функциональные требования (FR)

> Формализованные функциональные требования TenderSearch (проверяемые формулировки
> «Система должна …»). Связаны с US/BR (`01_user_stories.md`, `02_business_rules.md`),
> NFR (`04_Data_and_NFR/02_non_functional_requirements.md`) и этапами (`plans/plan.md`).
> Статусы: ✅ реализовано · 🟡 частично · ❌ отсутствует (актуализировано 2026-08-24).

## Группа 1. Профили фильтрации (Эпик 1)

| ID | Требование | Приоритет | US/BR | Статус | Этап |
| :-- | :--------- | :-------- | :---- | :----- | :--- |
| FR-1.1 | Система должна хранить профили фильтрации per-user (CRUD: создание, просмотр, обновление, удаление) с изоляцией по `user_id` (BR-07). | Must | US-1.1–1.4, BR-07 | ✅ | 1, 2 |
| FR-1.2 | Система должна хранить ключевые слова и слова-исключения профиля в таблице `keywords` (канонический источник), поддерживая синтаксис `слов*`, `(фраза* фраза*)~N`, точные фразы. | Must | US-1.1, US-1.3, BR-02 | ✅ | 2 |
| FR-1.3 | У каждого пользователя должен быть ровно один активный профиль (`is_active`); переключение деактивирует остальные. | Must | US-1.4, BR-07 | ✅ | 2 |
| FR-1.4 | Система должна позволять сид профиля из `data/profile.md` (`zp seed-profile` / `POST /api/clients/seed`). | Should | US-1.1, R8 | ✅ | 2 |
